# 백로그에 적기

사용자가 넘긴 것: `$ARGUMENTS`

이 스킬이 시작될 때 첫머리에 `Base directory for this skill: <경로>/skills/backlog-add`
가 주입된다. **그 경로를 기준으로** `../../scripts/backlog.mjs`를 node로 실행하라 —
아래 예시의 `<base>`는 그 Base directory의 **절대 경로**로 바꿔 넣는다. 백로그 문서를
찾는 뿌리는 **cwd의 git 저장소 뿌리**다(git이 아니면 cwd).

형식은 **스크립트가 쥔다**(ADR-091). 이 스킬은 부르고 결과를 보여 주기만 한다 —
`docs/BACKLOG.md`를 직접 편집하지 마라.

`$ARGUMENTS`가 `progress`로 시작하면 **3절로 곧장 간다**: 그대로 스크립트에 넘긴다.

```bash
node "<base>/../../scripts/backlog.mjs" $ARGUMENTS
```

## 0. 문서가 아직 없으면 (`init`)

어떤 명령이든 `docs/BACKLOG.md가 없습니다 — …`로 실패하면 이 저장소에는 아직 백로그가
없다. **만들지 물어보고**, 사용자가 "그래"라고 답한 뒤에 부른다:

```bash
node "<base>/../../scripts/backlog.mjs" init
```

- 「대기 중인 요구」·「사람 몫」 절과 자리표시자만 있는 골격이 생긴다. 장기 방향 절은
  첫 `add --long`이 만든다.
- 이미 있으면 `이미 있습니다`라고만 하고 **아무것도 덮지 않는다**.
- **마음대로 만들지 마라** — 문서를 두는 것은 그 저장소의 작업 방식을 정하는 일이다.
  만든 뒤에는 원래 하려던 명령을 다시 부른다.

## 1. 대기 중인 요구 한 줄 (기본)

제목을 **따옴표 하나로 묶어** 부른다:

```bash
node "<base>/../../scripts/backlog.mjs" add "<제목 — 요약>"
```

- 제목과 요약은 em dash `—`로 가른다. 요약이 없으면 제목만 넘긴다.
- 날짜는 `Asia/Seoul`의 오늘이 기본값이고, 맥락은 지금 브랜치에서 온다
  (`feature/x` → `x 작업 중 들어옴`).
- **`main`처럼 맥락을 유추할 수 없는 브랜치**면 스크립트가 실패하며 `--context`를
  요구한다. 그때 사용자에게 "어떤 일 도중에 들어온 요구인지" 한 번 물어
  `--context "…"`를 붙여 다시 부른다. 맥락을 지어내지 마라.
- 같은 제목이 이미 있으면 스크립트가 `이미 있습니다`라고만 하고 끝난다(정상).

## 2. 장기 방향 (`--long`)

```bash
node "<base>/../../scripts/backlog.mjs" add --long "<제목>" --state "현 상태" --next "잔여 방향" --open "미결 질문"
```

세 칸이 **모두** 있어야 한다. 하나라도 비면 스크립트가 아무것도 쓰지 않고 멈춘다.
사용자가 제목만 줬다면 **먼저 셋을 묻고**(AskUserQuestion 한 번, 또는 산문으로 세
질문) 답을 받아 명령을 부른다:

1. 지금은 어디까지 돼 있나? (현 상태)
2. 남은 방향은? (잔여 방향)
3. 아직 못 정한 것은? (미결 질문)

`--todo "…"`(미완)와 `--done "…"`(완료)을 여러 번 붙이면 **진행 체크리스트**를
처음부터 친 순서대로 심는다(선택 — ADR-092). 잔여 방향이 ①②③처럼 갈래로 나뉘면
갈래마다 하나씩 넣고, 이미 된 갈래는 `--done`으로 적는다:

```bash
node "<base>/../../scripts/backlog.mjs" add --long "…" --state "…" --next "…" --open "…" \
  --done "① 읽기 — Apple 캘린더" --todo "② Google Calendar API 소스"
```

## 3. 진행 갱신

"B-7 ① 다 됐어"·"체크해 줘"처럼 **어디까지 됐는지**를 알려 오면 이 절이다. 이미
있는 장기 항목의 진행은 **`docs/BACKLOG.md`를 손으로 고치지 말고** 이 명령으로
바꾼다(ADR-092):

```bash
node "<base>/../../scripts/backlog.mjs" progress B-7 --check "① 쓰기"      # 있는 항목을 완료로
node "<base>/../../scripts/backlog.mjs" progress B-7 --uncheck 2           # 번호(1부터)로 되돌리기
node "<base>/../../scripts/backlog.mjs" progress B-7 --done "…" --todo "…" # 항목 더하기(완료/미완)
```

- `--check`/`--uncheck`는 **있는 항목만** 고른다(번호나 본문 일부). 본문이 둘 이상과
  맞으면 스크립트가 멈추고 번호를 요구한다 — 그때는 후보를 보고 번호로 다시 부른다.
- `--done`/`--todo`는 없으면 더하고 **이미 있으면 그 상태로 맞춘다** — 항목 본문을
  아는 채로 "이거 됐어"를 옮길 때는 이쪽이 편하다.
- 어떤 항목이 있는지 모르면 먼저 `list --section 장기`로 본다.
- 체크리스트는 **코드와 대조한 사실**이어야 한다. 확인하지 않은 것을 완료로 찍지
  마라 — 스크립트는 형식만 쥐고 사실은 모른다.
- 보기만 할 때는 `/backlog`.

## 4. 사람 몫 — 에이전트가 아니라 사람이 하는 것

사용자가 "이건 내가 해야 돼"·"나한테 남겨 둬"라고 하거나, **당신(Claude)이 사용자에게
사람만 할 수 있는 한 걸음을 넘길 때** 이 절이다 — 설정에서 연동을 켜기, 첫 승인 카드를
직접 승인하기, 개발 서버를 사용자가 띄우기처럼 에이전트가 대신 못 하는 일. 말로만
안내하면 세션이 바뀌는 순간 사라져 같은 안내를 다시 하게 된다(ADR-093 ②).

```bash
node "<base>/../../scripts/backlog.mjs" mine add "<할 것 — 설명>" --source "…"
```

- **`--source`는 필수다.** 그 일을 남긴 근거를 한 구로 적는다(예: `--source "ADR-082,
  2026-09-02 대화"`). 없으면 스크립트가 멈춘다 — 출처 없는 줄은 며칠 뒤 "이걸 왜 해야
  하지"가 되고, 그러면 지울 수도 할 수도 없다.
- 절이 없으면 스크립트가 만든다. 대기 줄과 문법이 같다(`할 것 — 설명`).
- 보기만 할 때는 `/standup` 또는 `mine list`.
- 사람이 하기 전에 **대신 해 주지 마라** — 무엇이 사람 몫인지 판단한 그 이유가 그대로
  "에이전트는 제안하고 사람이 적용한다"이다.

## 5. 지우기 — 끝난 것은 남기지 않는다

백로그 규칙은 "구현이 머지되는 즉시 그 항목을 삭제한다"이다. 그 삭제를 손으로 하면
규칙 자체가 깨진다 — 명령으로 한다(ADR-093 ③). **`docs/BACKLOG.md`를 손으로 고치지 마라.**

```bash
node "<base>/../../scripts/backlog.mjs" done "구현 진행 상황 스킬"   # 대기 줄이 머지됐을 때
node "<base>/../../scripts/backlog.mjs" mine done 2                  # 사람 몫을 사용자가 끝냈을 때
node "<base>/../../scripts/backlog.mjs" done --long B-2              # 장기 방향이 다 구현됐을 때 (절을 통째로)
```

- 번호(1부터)나 본문 일부로 고른다. 본문이 둘 이상과 맞으면 스크립트가 멈추고 번호를
  요구한다 — 그때는 후보를 보고 번호로 다시 부른다.
- 절이 비면 `- (없음)` 자리표시자가 되살아난다.
- **`--long B-N`은 절 하나를 통째로 지운다**(진행 블록까지, ADR-109). 진행 체크리스트가
  **전부 완료**가 아니면 스크립트가 거절한다 — 남은 항목을 보여 주므로, 정말 끝났으면
  먼저 `progress B-N --check …`로 체크하고 다시 부른다. 그래도 지우려면 `--force`인데,
  그것은 **사용자가 지우라고 말했을 때만**이다.
- 나머지 B-N 번호는 **다시 매기지 않는다** — ADR·계획이 그 번호를 이름으로 가리킨다.
  빈 번호가 생기는 것이 정상이다.
- **지울지는 사람이 정한다.** ⚠("나중에 나옴 — 머지된 듯, 삭제 검토"·"진행 전부 완료")는
  힌트일 뿐이니 묻고 나서 지운다. 사람 몫은 특히 그렇다 — 사용자가 그 일을 했는지
  스크립트도 당신도 모른다.

## 6. 마무리

- 스크립트가 출력한 **추가된 줄을 그대로 보여 준다**.
- **커밋하지 않는다.** 백로그 줄은 지금 하던 작업의 커밋에 함께 실린다.
- 적었으면 하던 일로 곧장 돌아간다 — 백로그는 미루기 위한 것이지 새 일을 시작하기
  위한 것이 아니다.
