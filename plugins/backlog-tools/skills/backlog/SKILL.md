# 백로그 보기

이 스킬이 시작될 때 첫머리에 `Base directory for this skill: <경로>/skills/backlog`
가 주입된다. **그 경로를 기준으로** `../../scripts/backlog.mjs`를 node로 실행하라 —
스크립트는 플러그인 캐시 안에 있고, 사용자의 저장소는 지금 있는 곳(cwd)이다.

```bash
node "<base>/../../scripts/backlog.mjs" list $ARGUMENTS
```

`<base>`는 위에서 받은 Base directory의 **절대 경로**로 바꿔 넣는다. 백로그 문서를
찾는 뿌리는 **cwd의 git 저장소 뿌리**다(git이 아니면 cwd) — 다른 저장소를 보려면
`--root <dir>`를 붙인다.

- 출력을 **그대로** 보여 준다. 표를 다시 그리거나 요약해 바꾸지 마라 — 형식은
  스크립트가 쥔다(ADR-091).
- 표에 **진행** 열과 「**진행 상황**」 블록이 함께 나온다.
- 표 셋 모두에 「**작성**」 열이 있다 — 그 줄을 적은 도구(`claude`·`codex` 등)이고,
  사람이 터미널에서 직접 친 줄과 이 기능(ADR-121) 이전의 옛 줄은 **빈 칸**이다.
- 마지막 줄의 정직성 점검 건수를 **한 줄로** 짚어 준다. ⚠가 있으면 그 항목이 왜
  걸렸는지 한 마디만 덧붙인다:
  - `ADR-NNN 나중에 나옴` — 아직 할 일이 가리키는 결정이 **그 항목을 적은 뒤에**
    나왔다(`docs/CHANGELOG.md`의 날짜 기준, ADR-109). 그 사이에 구현됐을 수 있다.
    적을 때 **이미 있던** ADR은 ⚠가 아니다 — 그것은 "바꾸겠다"고 가리킨 결정이다.
  - `ADR-NNN 변경 기록에 없음` — 그 ADR이 언제 나왔는지 알 수 없다. 확인할 거리다.
  - `30일 초과` / `진행이 전부 완료`.
  - 저장소에 `docs/ADR.md`·`docs/CHANGELOG.md`가 없으면 ADR ⚠는 **아예 뜨지 않는다**
    — 견줄 것이 없는 것이지 위반이 아니다.
- **아무것도 지우지 마라.** ⚠는 힌트일 뿐이고 삭제는 사람이 정한다 — 백로그는
  사람의 약속 목록이다(ADR-091 트레이드오프). 지울지 물어보기만 한다.
- 이 스킬은 읽기 전용이다. 줄을 더하려면 `/backlog-add`.

## 문서가 아직 없으면 — 묻고 나서 만든다

출력이 `docs/BACKLOG.md가 없습니다 — …`  한 줄이면 이 저장소에는 아직 백로그가 없다
(오류가 아니다). 그 줄을 그대로 보여 주고 **만들지 물어라**:

> 이 저장소에는 아직 `docs/BACKLOG.md`가 없습니다. 골격을 만들까요?

사용자가 "그래"라고 답한 뒤에야 부른다:

```bash
node "<base>/../../scripts/backlog.mjs" init
```

- **마음대로 만들지 마라.** 문서를 두는 것은 그 저장소의 작업 방식을 정하는 일이다.
- 이미 있으면 `init`은 `이미 있습니다`라고만 하고 아무것도 덮지 않는다.

## 진행이 비어 있으면 — 묻기만 한다

장기 항목의 진행 열이 `—`인 것이 있으면(체크리스트가 아직 없다는 뜻) **한 번만**
묻는다(AskUserQuestion 한 번, 또는 산문으로 한 줄):

> B-3·B-5의 진행이 비어 있습니다. 코드와 대조해
> `progress B-N --todo "…" / --done "…"` 로 채울까요?

- **묻기만 하고 채우지 마라.** 사용자가 "채워 줘"라고 답한 뒤에야 코드를 대조하고
  그 명령을 부른다 — 체크리스트는 사실이어야 하고, 사실은 스크립트가 모른다
  (ADR-092 트레이드오프).
- 답이 "아니오"거나 답이 없으면 그대로 둔다. 다시 묻지 마라.
- 지우자는 제안은 하지 않는다 — ⚠ "진행 전부 완료"도 삭제 검토 신호일 뿐이다.
