# 지시서 원형 8종

`<…>`는 채울 자리다. `{{PROJECT:…}}`는 `PROJECT.md`의 해당 절을 **그대로 복사해 넣을** 자리다. 작업자는 PROJECT.md를 보지 못한다.

지시서는 `$STATE/spec-<종류>-<slug>[-N].md` 파일로 쓰고 `--spec "$(cat FILE)"`로 넘긴다.

---

## 8. 출시 — 머지 주체=서브에이전트 (조율자의 git 서브에이전트 · Agent 도구) — 프롬프트

```

- 보고 형식: {{PROJECT:보고 형식}}

[대상]
- worktree: <구현 wt> / 로컬 브랜치: <이름> / HEAD: <전체 sha>
- 기준: origin/<기준> <sha>(<버전>)이 이미 이 브랜치의 조상이다.

1. 확인(읽기 전용): worktree가 깨끗하고 HEAD가 <sha>인지. git fetch origin 뒤 origin/<기준>이 HEAD의 조상인지. origin/<기준>이 <sha>에서 움직였으면 멈추고 보고한다(머지·리베이스를 직접 하지 말 것).
2. 머지 전 게이트: {{PROJECT:머지 전 게이트}}. 하나라도 실패하면 멈춘다.
3. 브랜치를 {{PROJECT:원격 브랜치 이름 규칙}}으로 origin에 푸시한다. 강제 푸시 금지.
4. PR: base <기준>, 제목 <…>. 본문은 {{PROJECT:PR 템플릿}}을 따르고 <결정 기록 번호>를 명시한다. 본문 끝에 {{PROJECT:PR 서명 줄}}.
5. CI를 끝까지 기다린다. 시작할 때 부하를 기록한다({{PROJECT:CI 부하 기록}}). 실패하면 실패한 테스트와 로그 요지를 확인하고 재실행하지 말고 멈춰 보고한다.
6. CI가 초록이면 머지 직전에 다시 fetch해 origin/<기준>이 그대로인지 확인한 뒤 gh pr merge <번호> --merge --match-head-commit <전체 sha>. 원격 브랜치는 지우지 않는다.
7. 로컬 기준 브랜치 체크아웃을 git pull --ff-only로 맞춘다. 건드리지 않을 것(커밋·되돌리기·stash 금지): <추적 안 된·수정된 파일 목록>. 이 브랜치가 커밋한 계획서와 같은 경로의 추적 안 된 파일이 ff를 막으면 지우지 말고 <상태 폴더>/moved-main-<파일명>으로 옮긴 뒤 다시 pull하고, 옮긴 사실과 차이 요지를 보고한다. 그래도 ff가 안 되면 멈춘다.
8. 태그: 로컬과 원격 태그가 일치하는지 확인(이번에 올라가는 것은 <vX.Y.Z> 하나뿐). 머지 커밋에 annotated <vX.Y.Z>(메시지 「<vX.Y.Z> — <요지> (<결정 기록 번호>)」). {{PROJECT:태그 푸시}}. non-fast-forward면 멈춘다. 강제 푸시는 항상 금지.
9. 릴리스: {{PROJECT:릴리스 명령}}(이미 있으면 만들지 않는다).

[제약] {{PROJECT:금지 구역}} / 기준·main 브랜치 직접 푸시 금지 / 강제 푸시 금지 / 새 커밋이 필요하면 메시지 끝에 {{PROJECT:커밋 서명 줄}}.

[보고에 담을 것] PR 번호·URL · CI 실행 id·결과·부하 · 머지 커밋 해시 · 태그·릴리스 URL · main 체크아웃 git status --porcelain · 옮긴 파일.
```

## 8b. 출시 — 머지 주체=사람 (조율자의 git 서브에이전트 · Agent 도구) — 프롬프트

`PROJECT.md` §머지 주체가 「사람」인 저장소용이다. PR과 CI까지만 하고 멈춘다.

```
<프로젝트> 저장소에서 리뷰가 끝난 기능 브랜치 하나를 푸시하고 PR을 열어 CI 결과까지 보고해 줘. **머지·태그·릴리스는 하지 않는다.** 이 저장소는 사람만 머지한다.
- 로컬 기준 브랜치 체크아웃: <경로> / 리모트 origin: <url>
- 보고 형식: {{PROJECT:보고 형식}}

[대상]
- worktree: <구현 wt> / 로컬 브랜치: <이름> / HEAD: <전체 sha>
- 기준: origin/<기준> <sha>이 이미 이 브랜치의 조상이다.
- 커밋: <sha 제목> …
- 내용: <사용자 언어 서너 줄> · <결정 기록 번호>
- 구현자가 게이트를 모두 exit 0으로 통과시켰다: <게이트 목록>.

[순서]
1. 확인(읽기 전용): worktree가 깨끗하고 HEAD가 <sha>인지. git fetch origin 뒤 origin/<기준>이 HEAD의 조상인지. 움직였으면 멈추고 보고한다(머지·리베이스를 직접 하지 말 것).
2. 머지 전 게이트: {{PROJECT:머지 전 게이트}}. 하나라도 실패하면 멈춘다.
3. 브랜치를 {{PROJECT:원격 브랜치 이름 규칙}}으로 origin에 푸시한다. 강제 푸시 금지.
4. PR: base <기준>, 제목 <…>. 본문은 {{PROJECT:PR 템플릿}}을 따르고 <결정 기록 번호>와 `Closes #<이슈>`를 적는다. 기준 브랜치 머지가 곧 배포인 저장소면 본문 첫 줄에 「⚠️ 머지 = <어디> 배포」를 적는다. 본문 끝에 {{PROJECT:PR 서명 줄}}.

6. 여기서 끝낸다. `gh pr merge`, 태그, 릴리스, 기준 브랜치 pull을 실행하지 않는다.

## 9. 조율자 인계 — 새 조율자 세션(다른 공급자 가능)에 붙여 넣는 프롬프트 — `$STATE/handoff.md`

조율자가 항목을 시작할 때 채워 두고 판마다 갱신한다(SKILL.md §4.12). 조율자가 한도로 멈추면 사람이 Orca 터미널에서 새 세션(Claude Code 또는 Codex)을 열고 이 파일 본문을 그대로 붙여 넣는다.

```

[먼저 읽기]
1. 스킬: <플러그인 경로>/skills/orca-pipeline/SKILL.md (§4.10 재개 순서, §4.12 모델 대체, §5 메시지 루프) · TEMPLATES.md
2. 프로젝트 값: <레포>/.claude/orca-pipeline.md (§모델 · §모델 대체 · §금지 구역 · §머지 주체)

[지금 상태 — 앞 조율자가 마지막으로 쓴 것]
- run: <run id> / 항목: <이름> (<결정 기록·버전>)
